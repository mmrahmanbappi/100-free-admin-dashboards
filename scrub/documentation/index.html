Scrub

A healthcare and clinical dashboard template. 36 pages, light and dark, no build step, no framework, no internet connection required.

HTML, CSS and vanilla JavaScript Light and dark themes Works offline Responsive to 390px

1. Getting started

Unzip the folder and open index.html in a browser. That is the whole setup. There is no npm install, no bundler and no server requirement, and every asset is local so the template works with no internet connection.

To publish, upload the folder to any static host. To use it inside an application, copy assets/ and treat each HTML page as a layout reference.

3. Re-skinning

Every colour, radius, shadow and font in the template resolves through a custom property. Open assets/css/scrub.css and edit the two blocks at the top: :root for light and [data-theme="dark"] for dark. Nothing below those blocks contains a colour literal, so one edit re-skins all 36 pages including the charts, which read their colours from the computed styles at runtime.

Three alternate schemes

Paste any of these over the accent and series values in :root.

/* Clinical cobalt */
--accent:#0B57C7; --accent-hover:#0A47A3; --accent-soft:#E4EDFC;
--canvas:#F2F5FA; --series-1:#0B57C7; --series-2:#1C5E7E; --series-3:#8C5A00;

/* Teal */
--accent:#0E7A86; --accent-hover:#0B616B; --accent-soft:#DDF0F2;
--canvas:#EFF7F8; --series-1:#0E7A86; --series-2:#1A6E52; --series-3:#8C5A00;

/* Slate, accent used sparingly */
--accent:#2E4057; --accent-hover:#223146; --accent-soft:#E6EBF1;
--canvas:#F2F4F7; --series-1:#2E4057; --series-2:#16715C; --series-3:#8C5A00;

The one rule you should not change

Status colour is reserved. --ok means stable, --warn means monitor and --crit means critical. Red is never used for a button, an accent or decoration anywhere in this template, so that a clinician seeing red on any screen knows it concerns a patient. If you re-skin, keep that rule. Acuity has its own five-step scale, --acu-1 through --acu-5, where 1 is most urgent.

Fonts

Change --font and --mono in :root. If you swap to a font you host yourself, add the @font-face rules to assets/css/fonts.css and drop the files into assets/fonts/. If you prefer Google Fonts over self-hosting, replace the fonts.css link in each page head with the Google stylesheet link.

Theme behaviour

The theme is set with a data-theme attribute on <html> and stored in localStorage under scrub.theme. A small inline script in every page head applies the stored value before first paint so there is no flash. To ship dark as the default, change data-theme="light" to data-theme="dark" in the page templates.

4. Replacing the demo data

Every figure on every page comes from assets/js/scrub-data.js. Nothing is hard coded into the HTML. Replace the contents of that file, keep the key names, and all 36 pages follow.

window.SCRUB_DATA = {
  settings:  { org, unit, currency, timezone, user },
  labels30:  [ "21 Aug", … ],          // x axis labels
  metrics:   { occupancy:{ label, value, delta, unit, dunit, series, invert? }, … },
  vitals:    [ { key, value, unit, ref, state, flag }, … ],
  spo2: [...], hr: [...],               // observation traces
  definitions:{ revenue:"…", … },       // tooltip text on metric labels
  patients:[], beds:[], appointments:[], medications:[], labs:[], staff:[], …
};

Metric unit is one of count, rate, pp, min, days or money. dunit says how the delta reads: abs for "+4 patients", pp for percentage points, or omit it for a percentage. Set invert:true on any metric where a fall is good, such as median wait or readmission rate, and the delta colours itself correctly without you changing the sign.

A vitals entry carries its own state: ok, warn or crit. The reference range is shown to the clinician rather than being applied as a rule, because the template does not calculate anything clinical.

To wire it to a real backend, fetch your data, shape it into the same object, assign it to window.SCRUB_DATA before scrub.js loads, and delete the demo file.

5. Building a page

Pages are declarative. You write markup with data attributes and the script fills it in.

AttributeWhat it renders
data-kpis="inClinic,waiting"A row of KPI cards with deltas and sparklines
data-vitals="6"The vitals strip, with reference ranges and automatic states
data-bedsThe bed board
data-chart="line|metric:occupancy"A chart. Kinds: line, area, bar, hbar, donut
data-chart="line|trace:spo2"An observation trace, labelled by time of day
data-band="95,100" data-threshold="92"Target band and dashed escalation threshold
data-chart="bar|list:departments:name:seen:6"A chart from any collection
data-compareAdds a dashed previous-period series
data-table="patients" data-cols='[…]'A full table from a collection
data-pickAdds row checkboxes and the floating bulk bar
data-filter-key="status"Lets filter chips filter rows by that field
data-bars="channels:name:revenue:4"A ranked bar list
data-feed, data-live-feedActivity feed, optionally live
data-funnel, data-cohortReferral pathway, cohort grid
data-act="modal" data-val="m-id"Opens that modal. Also drawer, toast, copy, print, busy

Table columns

data-cols='[
  {"t":"Patient","k":"name","f":"patient"},
  {"t":"Location","k":"location","n":1},
  {"t":"Acuity","k":"acuity","n":1},
  {"t":"Status","k":"status","f":"pill","tone":"tone"}
]'

t is the heading, k the key in the data row, n right-aligns and uses the mono face, and f picks a formatter: patient, person, link, num, money, pct, pill, meter, stars, delta, strong, sku, score.

7. Accessibility

  • Every interactive element is a real button or link, never a clickable div.
  • Visible focus rings on everything, and they are never removed.
  • Modals and drawers trap focus and return it to the trigger on close.
  • Escape closes, in order: command palette, modal or drawer, popover, mobile navigation.
  • Tables carry aria-sort, the live region is aria-live="polite".
  • Colour never carries meaning alone: deltas have arrows, statuses have text labels.
  • prefers-reduced-motion is honoured.

8. Browser support

Current versions of Chrome, Edge, Firefox and Safari, desktop and mobile. The layout uses CSS logical properties throughout, so setting dir="rtl" on <html> mirrors the whole interface with no second stylesheet.

10. Clinical safety

This is a user interface template. It is not a medical device, it performs no clinical calculation, and it must not be used to make clinical decisions. The reference ranges and escalation thresholds in the demo data are illustrative only.

If you deploy this interface in a clinical setting, the clinical safety case, the validation, and compliance with the medical device and data protection rules of your jurisdiction are your responsibility. Patient identifiers in the demo data are invented and no real record is included.
